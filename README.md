# toolkina_repo
Bottle sort

## Запуск приложения

Интерфейс работает на JavaScript в Electron, а игровые правила и решатель остаются на Python.
Установите Node.js/npm и Python, затем из корня проекта выполните:

```sh
npm install
npm start
```

Для запуска того же интерфейса через Python используйте `python main.py`. Консольный прототип
по-прежнему запускается командой `python main.py --console`.

1. Общее описание проекта
Разработай десктопную игру-головоломку для ПК (Windows). Игрок переливает слои цветной жидкости между бутылками, чтобы в итоге каждая бутылка содержала только один цвет (полностью заполненная) либо была пустой.
Ориентация — горизонтальный экран, управление мышью

2. Основные игровые правила
2.1. Структура уровня
• На уровне есть N бутылок, каждая имеет фиксированную ёмкость C (например, 4 слоя).
• В бутылках послойно налита жидкость разных цветов. Каждый слой — один цвет.
• Общее количество цветов на уровне — K (варьируется по уровням).
• Количество «полных комплектов» каждого цвета = C (то есть каждый цвет встречается ровно C раз во всех бутылках — это гарантирует, что цель достижима в принципе).
• Часть бутылок изначально пустая (обычно 1–3 в зависимости от сложности) — они служат буфером для переливаний.
2.2. Правила переливания
1. Переливать можно только из верхнего слоя бутылки-источника.
2. Переливать можно только в пустую бутылку или на слой того же цвета в бутылке-приёмнике.
3. За одно переливание переносится весь непрерывный блок верхних слоёв одного цвета (сколько поместится в приёмник по свободному объёму). Классический вариант: переливается весь верхний блок одного цвета, но не больше, чем свободного места в приёмнике.
4. Нельзя переливать из бутылки в неё же.
5. Нельзя переливать, если бутылка-приёмник заполнена.
2.3. Условие победы
Уровень пройден, когда каждая бутылка либо пуста, либо полностью заполнена слоями одного цвета (C слоёв одного цвета).

3. Генерация уровней (критически важное требование)
3.1. Гарантия решаемости
Все уровни обязаны иметь решение. Реализуй генерацию одним из двух способов (предпочтительно — комбинировать):
Способ А — обратная генерация (reverse shuffle):
1. Создай «решённое» состояние: K бутылок, каждая полностью заполнена одним цветом, плюс E пустых бутылок.
2. Выполни серию обратных переливаний (валидных ходов в обратную сторону), перемешивая слои.
3. Полученное состояние по построению решаемо (решение — обратный порядок ходов).
4. Отбрось состояния, где уровень уже решён, или где решение тривиально (проверка эвристикой «минимум ходов»).
Способ Б — прямая генерация + верификация:
1. Сгенерируй случайное распределение слоёв с соблюдением условия «каждый цвет встречается ровно C раз».
2. Запусти решатель (BFS/A* с мемоизацией состояний) с ограничением по времени/памяти.
3. Если решение найдено — принять уровень; если нет — перегенерировать.
Обязательно: добавь в редактор/дебаг-режим кнопку «Проверить решаемость» и автоматический тест на этапе сборки контента: прогон всех уровней кампании через решатель.
3.2. Кривая сложности (геометрическая прогрессия)
Сложность должна расти экспоненциально. Предлагаемая метрика сложности:
S(level) = K * C * (1 + E_penalty) * (1 + M)
где K — число цветов, C — ёмкость, E_penalty — штраф за малое число пустых бутылок, M — множитель дополнительных механик.
Рекомендуемая прогрессия по уровням (пример, C=4):
Диапазон уровней K (цветов) Пустых бутылок Доп. механики
1–10 3 → 5 2 —
11–25 5 → 8 2 —
26–45 8 → 12 1–2 Заблокированные бутылки
46–70 12 → 18 1 «Камень» (непереливаемый слой)
71–100 18 → 26 1 Комбинация механик, ёмкость 5
101+ 26+ 0–1 Все механики, процедурная генерация
Формула роста: K(n) = ceil(K0 * r^n), где r ≈ 1.06–1.1, K0 = 3. Настрой параметры так, чтобы число цветов удваивалось примерно каждые 10–12 уровней.
Важно: сложность растёт за счёт числа цветов и механик, а не за счёт «нерешаемых» конфигураций. Все уровни проходят верификацию решателем.
3.3. Дополнительные усложнения (появляются постепенно)
Реализуй как отдельные флаги уровня, включаемые по мере прогресса:
1.  «Каменный» слой — слой, который нельзя перелить; он «открывается», только когда над ним не остаётся жидкости (или после специального действия).
2. Ёмкость 5+ — бутылки на 5–6 слоёв.
3.  «Замороженный» слой — требует двух одинаковых переливаний подряд или разморозки.
4. Бутылка-«обманка» — бутылка, которую нельзя использовать как приёмник до выполнения


условия.
5. Тёмные/скрытые слои — цвет нижних слоёв виден только после открытия верхних (опционально, для хардкора).
Правило: каждая механика должна быть проверена решателем на решаемость с учётом её правил. Механики вводятся по одной, с туториальным уровнем на каждую.

4. Пользовательский интерфейс и UX
• Главное меню: Играть / Выбор уровня / Настройки / Выход
• Экран уровня:
o Бутылки в ряд (или сеткой при большом количестве).
o Счётчик ходов, таймер (опционально), кнопки «Отменить ход», «Перезапустить», «Подсказка».
o Индикатор прогресса уровня (сколько бутылок собрано).
• Управление: drag-and-drop жидкости из бутылки в бутылку или клик по источнику → клик по приёмнику. Подсветка валидных приёмников при выборе источника.
• Анимации: плавное переливание (1–2 сек), «волна» жидкости, лёгкий звук.
• Отмена хода: стек истории, минимум 20 шагов назад (или без ограничений).
• Подсказка: использует решатель — показывает следующий оптимальный ход (ограниченное число подсказок на уровень, опционально).
• Сохранение прогресса: автосохранение пройденных уровней и текущего состояния уровня (чтобы можно было продолжить).
• Настройки: звук, музыка, язык (RU/EN), сброс прогресса.

5. Визуальный стиль и звук
• Минималистичный, «чистый» стиль: стеклянные бутылки с бликами, яркие контрастные цвета жидкостей (палитра из 20+ различимых цветов, с учётом дальтонизма — добавить режим «цветовые паттерны»).
• Текстура жидкостей: добавляй жидкости разных приятных текстур, можно добавить что-то нетипичное типо лавы и тд
• Фон — спокойный градиент или нейтральный.
• Звуки: переливание, ошибка, победа. Лёгкая фоновая успокаивающая музыка (опционально, с возможностью отключить).
________________________________________
6. Технические требования
• Ядро правил — отдельный модуль без зависимостей от UI (чистые функции: canPour(state, from, to), applyPour, isSolved).
• Решатель — BFS/A* с канонизацией состояний (сортировка бутылок для симметрии), ограничение по времени (например, 2 сек на уровень при генерации).
• Генератор уровней — офлайн-скрипт/редактор, который создаёт паки уровней, прогоняет верификацию и сохраняет JSON. Кампания — набор таких паков.
• Производительность: 60 FPS, мгновенный отклик на ввод; уровень с 30+ бутылками должен работать без просадок.
• Платформы: Windows (обязательно)

8. Тестирование и критерии приёмки
Обязательные тесты:
1. Юнит-тесты правил переливания (все граничные случаи: пустая бутылка, полная, чужой цвет, перелив блока, частичный перелив).
2. Тест решаемости: каждый уровень кампании проходит решатель за разумное время; тест запускается в CI/на сборке.
3. Тест кривой сложности: число цветов на уровне N соответствует формуле прогрессии (с допуском).
4. Ручной плейтест: первые 10 уровней проходятся за < 2 мин каждый; поздние — требуют размышления, но не «угадайки».
Критерии готовности (Definition of Done):
• □
Игра запускается на Windows и стабильно работает.
• □
Реализованы все базовые правила из раздела 2.
• □
Кампания из ≥ 100 уровней с геометрическим ростом сложности.
• □
Все уровни проверены решателем (есть отчёт о верификации).
• □
Реализованы минимум 3 дополнительные механики с туториальными уровнями.
• □
Есть отмена хода, перезапуск, подсказка, сохранение прогресса.
• □
UI/UX соответствует разделу 4, есть настройки звука и языка.
• □
Написаны юнит-тесты ядра правил и тест решаемости уровней.
10. Ограничения и анти-требования
• Не допускается генерировать уровни без проверки решаемости «на глаз».
• Не допускается решать сложность увеличением чи/сла нерешаемых/случайных конфигураций.
